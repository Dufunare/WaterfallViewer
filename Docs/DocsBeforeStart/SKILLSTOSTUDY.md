# WaterfallViewer 技术清单与学习路线

**面向当前技术水平的实现准备清单（草案 v0.1）**

| 属性         | 内容                                                   |
| ------------ | ------------------------------------------------------ |
| **适用对象** | 目前会 JavaScript、正在学习 Rust、尚未系统接触前端框架 |
| **文档目的** | 明确需要掌握的技术、优先级、学习深度与推荐顺序         |
| **使用方式** | 不要一次学完全部内容；按阶段边做边补                   |
| **当前策略** | 先跑通最小闭环，再逐步扩展技术面                       |
| **更新时间** | 2026-03-25                                             |

## 文档说明

这份清单不是“先学完再开始”的大纲，而是“为了把项目做出来，当前最值得学什么”的优先级列表。重点是学到能落地，而不是一开始把所有概念吃透。

---

## 1. 你的当前起点与建议策略

- 优势：已经会 JavaScript，因此可以较快理解 Vue 组件、事件、响应式状态和基本前端调试。
- 进行中：正在学习 Rust，适合从本项目中挑最实用的那部分先掌握，例如文件遍历、结构体、Result、序列化与简单并发。
- 短板：前端框架经验不足，容易在一开始被生态和概念量吓住。
- 最合适的策略：只学习当前阶段必须用到的最小知识，不要在项目启动前把 Vue、Rust、Tauri、性能优化一次性全学完。

**学习原则**
按照“先能用，再理解；先主链，再扩展；先最小闭环，再做性能”的顺序推进。任何技术点，只要当前阶段还用不到，就可以暂时不深入。

## 4. 必须掌握的知识域（按阶段需求排序）

### 4.1 HTML / CSS 基础

| 知识点                        | 为什么要会                             | 掌握到什么程度才够                              |
| ----------------------------- | -------------------------------------- | ----------------------------------------------- |
| 盒模型、宽高、padding、margin | 瀑布流卡片和预览层都依赖稳定尺寸。     | 能看懂元素为什么被撑开、挤压、溢出。            |
| position / overflow / z-index | 预览层、遮罩层、滚动容器都离不开。     | 能自己写出弹层、滚动区和覆盖层。                |
| Flexbox / Grid                | 用于过滤面板、工具栏、空状态布局。     | 会做常见横向 / 纵向排版即可，不必追求高级技巧。 |
| 图片显示基础                  | object-fit、容器比例、占位都和它相关。 | 知道如何避免图片被拉伸变形。                    |
| 响应式与断点意识              | 窗口大小变化时，列数与布局会变化。     | 能根据容器宽度调整列数与面板摆放。              |

**最小练习**
先用纯 HTML/CSS 做一个“固定宽卡片网格 + 点击放大预览”的静态页面。只要这个练习顺手了，进入 Vue 时心智负担会小很多。

### 4.2 TypeScript 基础

| 知识点             | 项目里的用途                                         | 掌握标准                              |
| ------------------ | ---------------------------------------------------- | ------------------------------------- |
| type / interface   | 定义 MediaItem、LayoutItem、ViewerState 等核心结构。 | 能自己写和维护前端数据结构。          |
| 联合类型           | 区分 image / video / audio 等媒体类型。              | 能基于 kind 写清晰分支逻辑。          |
| 可选字段与空值处理 | width / duration 等字段并非总是存在。                | 会处理 undefined / null，不滥用 any。 |
| 函数类型           | 给 composables、事件处理函数和布局函数写清晰签名。   | 能为纯函数和组件 props 标注类型。     |
| 基础泛型           | 对返回列表、状态容器有帮助。                         | 看得懂常见写法即可，不必深挖。        |

### 4.3 Vue 基础

| 知识点                          | 为什么关键                                           | 掌握标准                             |
| ------------------------------- | ---------------------------------------------------- | ------------------------------------ |
| 组件与 props                    | 整个 UI 都会被拆成组件。                             | 能把列表、卡片、预览层拆开写。       |
| ref / reactive / watch          | 列表数据、选中项、过滤条件、扫描状态都需要。         | 能理解响应式状态变更与副作用触发。   |
| 条件渲染与列表渲染              | 空状态、加载中、预览层开关、媒体项渲染都依赖。       | 能稳定写出 v-for 渲染与 key。        |
| computed / watchEffect 基础意识 | 布局结果和大量列表渲染时能减少不必要重算。           | 知道何时可能需要，而不是机械使用。   |
| refs 与 DOM 交互                | 滚动容器、滚动位置恢复、Intersection Observer 需要。 | 会获取滚动容器引用并读取 scrollTop。 |
| composables                     | 适合封装扫描流程、viewer 状态、窗口大小监听。        | 能把页面逻辑从组件模板中抽离出来。   |

**最小练习**
在进入 Tauri 之前，先做一个 Vue 小页面：从本地 JSON 读取图片列表，调用独立布局函数渲染一个可滚动图片流，并支持点击打开预览。

### 4.4 Tauri 基础

| 知识点                       | 项目里的用途                     | 掌握标准                             |
| ---------------------------- | -------------------------------- | ------------------------------------ |
| invoke / command             | 前端调用 Rust 扫描命令。         | 能让前端成功拿到 Rust 返回的数据。   |
| 事件通信                     | 后续扫描进度、批次结果需要。     | 第一闭环可先了解概念，第二阶段实现。 |
| 原生对话框                   | 选择目录是第一闭环入口。         | 能调用目录选择并拿到路径。           |
| 本地资源展示                 | 前端展示本地文件时要走受控链路。 | 知道不要直接随意拼 file://。         |
| capability / permission 思想 | 控制目录访问边界和窗口权限。     | 理解“默认不放开，按需要授权”的原则。 |

### 4.5 Rust 基础

| 知识点                | 项目里的用途                           | 掌握到什么程度才够                         |
| --------------------- | -------------------------------------- | ------------------------------------------ |
| struct / enum         | 定义 MediaItem、错误类型、媒体类型。   | 能写出稳定的数据模型。                     |
| Result / Option / ?   | 处理文件读取失败、元数据缺失等情况。   | 能读懂并写出常见错误传播。                 |
| ownership / borrowing | 遍历路径、返回结构、避免无谓 clone。   | 能在简单服务层代码中不被编译器完全卡住。   |
| 模块拆分              | 把 commands、services、models 分开。   | 知道何时把函数从 main.rs 拆出去。          |
| 迭代器与集合          | 处理目录遍历结果、筛选媒体文件。       | 能完成 map / filter / collect 等常见操作。 |
| serde                 | 前后端通过 JSON / IPC 交换结构化数据。 | 会给结构体派生 Serialize / Deserialize。   |
| 基础并发意识          | 后续需要控制扫描、缩略图、预览任务。   | 第一阶段只需理解“重活不要堵住 UI”。        |

**Rust 不必一开始学太深**
你不需要在项目开始前先搞懂高级生命周期、复杂 trait 设计或异步运行时内部原理。第一阶段只要能稳定写出“扫描目录并返回图片宽高”的小服务，就已经足够推进项目。

### 4.6 性能与媒体相关知识

| 主题                  | 当前是否必须 | 说明                                       |
| --------------------- | ------------ | ------------------------------------------ |
| 宽高比与占位计算      | 必须         | 没有稳定占位，瀑布流会跳动。               |
| 虚拟滚动基本原理      | 必须         | 这是项目成立的核心，而不是可选优化。       |
| Intersection Observer | 建议尽快掌握 | 用于资源懒加载，而不是扫描文件。           |
| 缩略图与缓存          | 第二阶段     | 理解概念即可，稍后实现。                   |
| 视频 / 音频元数据     | 中后期       | 先了解需求，不急于同时攻克。               |
| Benchmark 思维        | 中期         | 当真实目录规模上来后，才需要系统测量瓶颈。 |

## 5. 推荐库 / crate 清单（按实用性分类）

| 类别          | 建议项                                          | 作用                                | 是否一开始就需要               |
| ------------- | ----------------------------------------------- | ----------------------------------- | ------------------------------ |
| 前端基础      | Vue 3 + TypeScript + Vite                       | 前端界面与开发环境基线。            | 是                             |
| 前端状态      | Vue composables；必要时加轻量 store（如 Pinia） | 管理扫描状态、过滤器、viewer 状态。 | 先 composables 即可            |
| 虚拟滚动      | 可先自写最小版；也可后续引入成熟库              | 控制可见区域 DOM 数量。             | 第一阶段建议至少自写最简可用版 |
| Tauri         | Tauri 核心、对话框与 IPC 能力                   | 桌面壳、命令通信、目录选择。        | 是                             |
| Rust 数据模型 | serde / serde_json                              | 前后端数据结构序列化。              | 是                             |
| Rust 错误处理 | anyhow / thiserror（二选一或组合）              | 把扫描和解析错误写得更清晰。        | 强烈建议                       |
| 目录遍历      | walkdir                                         | 递归扫描文件目录。                  | 是                             |
| 图片尺寸读取  | imagesize 或等价能力                            | 不完整解码图片即可读取宽高。        | 是                             |
| 并发          | rayon 或后续任务池                              | 批量元数据解析与缩略图任务。        | 第一闭环可暂缓                 |
| 视频 / 音频   | 后续再评估专用 crate 或外部能力                 | 时长、首帧、封面、波形。            | 否                             |

## 6. 按阶段安排你的学习顺序

| 阶段     | 你需要先会什么                                                                   | 建议练习                                                  |
| -------- | -------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 开始前   | HTML/CSS 基础、JavaScript 到 TypeScript 的过渡、Vue 组件和响应式状态的最小概念。 | 做一个静态图片流页面。                                    |
| 第一闭环 | Tauri 基础、Rust struct / Result / 目录遍历、前后端 IPC。                        | 做一个“选目录 -> Rust 返回图片列表 -> 前端显示”的小链路。 |
| 第二阶段 | 独立布局函数、虚拟滚动、过滤器与滚动状态管理。                                   | 把静态列表替换为真正布局计算与可视窗口渲染。              |
| 第三阶段 | 预览层、键盘交互、滚动位置恢复。                                                 | 实现点击、关闭、上一张 / 下一张。                         |
| 性能强化 | Intersection Observer、并发限制、缩略图缓存、基础性能分析。                      | 面对更大的目录做体验调优。                                |
| 媒体扩展 | 视频 / 音频解析和占位设计。                                                      | 逐步扩展 mixed media 能力。                               |

## 7. 现阶段不建议你过早投入的内容

- 不要在第一闭环前把状态管理框架、路由框架、CSS 方案全部研究一遍。
- 不要在图片主链没跑通前急着同时做视频、音频、缩略图缓存和数据库。
- 不要为了“架构漂亮”一开始写过多抽象层、泛型工具或复杂 trait。
- 不要把主要精力花在 UI 动画和视觉 polishing 上，先把主链路与边界做对。
- 不要在前端里直接承担图片尺寸探测、批量资源读取和重 CPU 处理。

## 8. 启动项目前的自检清单

- 我能用 Vue 写出一个最小列表页面，并知道 props、响应式状态和监听机制的基本作用。
- 我能在 TypeScript 中定义一个 MediaItem 类型，并在组件中安全消费它。
- 我能运行一个最小 Tauri 示例，并从前端调用一个 Rust 命令拿到返回值。
- 我能用 Rust 扫描一个目录并输出所有图片文件路径。
- 我能写一个独立的布局函数：输入图片宽高和列数，输出每个卡片的坐标与高度。
- 我知道第一闭环的目标不是“做全功能产品”，而是“打通主链路”。
